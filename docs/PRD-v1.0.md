# PRD：高股息研究事实库与规则初筛 v1.0

## Problem Statement

投资者希望在本机研究中国 A 股和红利 ETF，以 200,000 元作为研究本金，找到可复核的高股息候选，而不是被某一天的静态收益率排名误导。现有本地数据库已覆盖全市场证券主表和日终价格，但低频分红、ETF 分配与财务事实尚未全市场完整；数据库还需要从可变的采集库升级为可重现的发布事实库。

用户需要一个公开、可审计的开源项目：每日或每周采集可继续运行，研究始终绑定到一个不可变发布版本，规则输出“资料足以研究 / 继续观察 / 不纳入本模板 / 资料不足”及理由，而不是买卖建议。首版不做自动交易、实时行情、个性化荐股或桌面端组合下单。

## Solution

构建一个本机优先的 Python/SQLite 发布与初筛系统。采集任务继续写入暂存数据库；发布器在临时目录校验并生成只读的 `facts.sqlite`、manifest、文件哈希和 `READY` 标记，然后原子切换当前发布指针。每个发布版本包含覆盖矩阵和数据水位，所有筛选结果写入独立的工作库并绑定 `release_id` 与 `rule_version`。

首版提供两类规则模板：稳健分红股票研究与红利 ETF 分散研究。股票以过去 12 个月已实施、税前、常规现金分红收益率为历史参考；特别分红单列；ETF 使用过去 12 个月实际现金分配率，绝不称为股息率或总回报。周期行业只可进入观察模板，不能进入稳健分红模板。所有结果都标明数据范围、截至日期和非推荐边界。

## User Stories

1. 作为投资者，我希望以 200,000 元记录研究本金，以便后续草案统一换算。
2. 作为投资者，我希望看到发布版本和价格日期，以便不把日终参考价当成实时价格。
3. 作为投资者，我希望知道全市场主表覆盖和低频事实覆盖分别是多少，以便理解候选范围的边界。
4. 作为投资者，我希望看到“资料不足”而不是空值被当作零股息率。
5. 作为投资者，我希望股票和 ETF 分开研究，以便不混淆公司分红与基金分配。
6. 作为投资者，我希望特别分红单列，以便不把一次性现金流当作常态。
7. 作为投资者，我希望周期股只作为观察对象，以便避免将景气高点的静态收益率误认为稳健现金流。
8. 作为投资者，我希望查看筛选理由和失败原因，以便人工复核。
9. 作为投资者，我希望保存某次筛选所用的版本，以便以后重现结论。
10. 作为投资者，我希望在历史事实不足时系统拒绝排名，以便避免伪精确比较。
11. 作为研究者，我希望每日采集只写暂存库，以便失败不会破坏上次发布版本。
12. 作为研究者，我希望发布过程先通过 SQLite 完整性校验，以便拒绝损坏的事实库。
13. 作为研究者，我希望 manifest 绑定事实库哈希与文件大小，以便证明读取的就是原发布内容。
14. 作为研究者，我希望发布切换是原子的，以便界面不会读到半成品。
15. 作为研究者，我希望发布包有 `READY` 标记，以便中断发布不会被误用。
16. 作为研究者，我希望每个数据域记录 as-of、可用截止时间、覆盖率、质量状态与来源运行编号，以便追溯。
17. 作为研究者，我希望覆盖矩阵按标的和数据集保存，以便规则可机械判断资料是否足够。
18. 作为研究者，我希望所有用于规则的事实带可得时间，以便避免使用未来披露的信息。
19. 作为研究者，我希望工作库与事实库分离，以便笔记、规则和结果不会改写事实。
20. 作为研究者，我希望规则版本化并显式声明参数、缺失策略和理由码，以便实现不依赖隐含默认值。
21. 作为研究者，我希望稳健分红规则要求常规分红历史、收益率/基准和行业约束，以便“资料完整”不被误解为“分红合格”。
22. 作为研究者，我希望 ETF 规则要求产品资料、分配/净值事件、流动性和跟踪品质，以便产品信息不足时被阻断。
23. 作为研究者，我希望结果排序只表示研究顺序，以便不形成买入评分。
24. 作为研究者，我希望新上市标的显示观察期未满，以便区别历史长度不足和公司质量问题。
25. 作为维护者，我希望引用于锁定研究的发布版本不可被清理，以便审计可重放。
26. 作为维护者，我希望保留、磁盘水位和兼容范围可配置并纳入版本控制，以便本机长期运行。
27. 作为维护者，我希望工作库在关键操作后备份，以便恢复时不丢失草案或规则。
28. 作为维护者，我希望新版本应用可只读旧发布包，以便升级不破坏历史研究。
29. 作为开源贡献者，我希望仓库不包含原始抓取数据、运行日志或个人数据库，以便公开协作安全且体积可控。
30. 作为开源贡献者，我希望测试可在离线临时数据库上运行，以便无需网络或市场数据也能验证发布协议。
31. 作为审阅者，我希望篡改事实文件、缺少 `READY`、哈希不符和不完整覆盖都会阻断读取，以便验证不可变性。
32. 作为审阅者，我希望资料完整但分红质量不合格的样本不能进入稳健模板，以便验证规则边界。
33. 作为审阅者，我希望股票分红、ETF 分配和总回报不混用，以便验证口径边界。
34. 作为未来桌面端用户，我希望仅访问已发布事实和工作库接口，以便界面不绕过数据门禁。

## Implementation Decisions

- 使用 Python 标准库和 SQLite 实现首个里程碑；现有采集器保持可用，发布器与初筛器不依赖网络。
- 发布包由事实 SQLite、manifest、各自 SHA-256、原始输入引用和 `READY` 组成。发布器只能在临时目录生成包，校验后原子重命名，再更新当前指针。
- 发布包与工作库分离。发布事实严格只读；工作库存放规则版本、筛选运行、筛选结果及未来的配置与草案。
- 覆盖矩阵以标的、数据集、历史窗口与发布版本为粒度，保存最新有效日期、最新可得日期、覆盖率、来源层级与质量状态。
- PIT 规则只允许使用发布时间不晚于发布截止时间的事实；缺发布时间或核验状态的关键事实不能使标的进入“资料足以研究”。
- 股票收益率固定为常规、已实施、税前、过去 12 个月每股现金分红除以对应发布日终收盘价；特别分红只显示，不进入稳健筛选分子。
- ETF 显示过去 12 个月实际现金分配率。拆分、合并、现金替代和分配事件资料不足时，该指标不可用。
- 所有规则都声明 scope、数据需求、必填参数、条件树、缺失策略、排序和理由码。`research_priority` 仅用于研究顺序，禁止作为投资评分。
- 规则输出只使用四个研究状态；不输出买卖、目标仓位、收益承诺、实时价格或自动下单。
- 公开仓库仅纳入代码、规则、空白/合成测试数据、文档和部署模板。数据库、原始数据、运行时目录、备份、日志和个人配置被忽略。

## Testing Decisions

- 测试只验证外部行为：发布能否被安全打开、是否可重放、是否正确拒绝不完整输入、规则是否产生正确状态与理由。
- 使用临时 SQLite 数据库和合成事实，不访问网络、不使用真实用户数据或运行时数据库。
- 覆盖发布协议：完整发布、事实文件篡改、manifest 篡改、缺 `READY`、当前指针原子切换和旧发布读取。
- 覆盖覆盖矩阵：全量价格、低频事实缺失、新上市观察期、发布时间晚于 cutoff 与质量失败。
- 覆盖规则：稳健分红的常规/特别分红分离、ETF 分配口径、周期股排除、参数缺失、排序非评分和资料不足。
- 保留并扩展现有 golden fixtures，确保高静态收益率陷阱不会被标记为稳健分红。

## Out of Scope

- 桌面端 UI、组合金额/数量草案、交易清单导出和券商连接。
- 自动交易、自动再平衡、实时行情、盘中预警、荐股或投资建议。
- 全市场低频事实的即时补齐与全市场高股息排行榜。
- 税后收益估算、个性化税务建议、回测和未来现金流预测。
- 将第三方原始数据、个人笔记或本地运行数据库上传到公开仓库。

## Further Notes

- 当前本地运行时已含 5,422 只股票、1,603 只 ETF、全市场日终价格与核心低频事实；这只是首个发布包的数据基础，不等于全市场分红质量已经完整。
- 数据更新仍以免费来源交叉校验为原则；由于研究非超短线，正确性和可追溯性优先于时效。
- 下一阶段在本 PRD 的数据与规则基础稳定后，才设计桌面端和组合草案。
