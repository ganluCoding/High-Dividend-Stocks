# 《中国 A 股高股息个股与 ETF 研究系统 PRD》评审复盘

- 评审对象：`docs/PRD.md` Draft v0.1
- 评审日期：2026-08-09
- 评审方式：三位独立审阅者先独立评审，再进行交叉回应
- 文件状态：评审记录，不直接修改 PRD

## 评审角色

1. **资深中国权益投资顾问**：检查投资目标、资产配置、高股息研究逻辑、决策边界和组合适配。
2. **资深软件架构与 Coding 专家**：检查工程可行性、领域模型、外部依赖、MVP 边界、测试与运维。
3. **量化研究方法与金融数据治理专家**：检查 point-in-time、幸存者偏差、公司行动、ETF收益口径、税费、数据血缘与可复现性。

## 总体评审结论

三位审阅者一致给出：**有条件通过**。

PRD v0.1 对研究原则的定义正确，尤其是：

- 不把静态股息率直接等同于投资收益；
- 将个股和 ETF 分开建模；
- 将历史分红升级为可持续分红、含分红总回报和组合穿透研究；
- 强调数据来源、时点、版本、反证和可审计性；
- 明确产品不是自动荐股或自动交易系统。

但当前文档更接近“终局愿景与能力清单”，还不是可以直接进入全功能开发的实施级 PRD。50 条用户故事没有 Must/Should/Could 优先级，投资决策规则、核心公式、数据契约、外部数据可得性和量化验收仍不充分。

本轮只批准进入：**数据与公式可行性 Spike**。

在 P0 修订和 golden tests 通过前，不批准：

- 全市场自动采集；
- 全功能系统开发；
- 全行业专属模型铺开；
- 策略回测或收益归因；
- 输出正式投资候选或“适合购买”结论。

## 三方共同确认的问题

### 1. 必须先定义“适合谁”，再判断“适合什么”

现有 PRD 虽然记录现金流目标、期限和回撤，但不足以形成资产配置判断。P0需要增加最小投资政策说明（IPS）：

- 可投资资产、负债与应急金；
- 高股息仓在总资产中的任务和目标权重；
- 现金需求金额、月份、消费或再投资安排；
- 投资期限、权益上限、最大可承受永久损失；
- 单一发行人、行业、经济驱动、央国企和低流动性暴露上限；
- 禁投范围、账户类型与税务身份；
- 当前收入型与股息增长/总回报型目标；
- 与“宽基指数+规则化卖出/现金缓冲”方案的对照。

关键 IPS 输入缺失时，系统只能输出研究资料，不能判断某标的是否“适合”。

### 2. 必须修正三个投资语义

1. **持仓成本股息率（yield-on-cost）**只用于回顾历史现金收入，不得用于横向估值、继续持有或候选排序。
2. 图片公式得到的不是“内在价值”或确定目标价，应命名为**目标收益率隐含价格**。
3. 即使隐含股息率达到目标，仍须通过企业质量、母公司可分红能力、资产负债表、周期正常化、独立估值、预期总回报和组合护栏的否决测试。

决策口径应以“保守前瞻分红 ÷ 当前可变现市值”为基础，同时呈现总回报与独立估值；不能因历史成本较低而忽略当前机会成本。

### 3. 税后收益不能给出伪精确值

个股股息税负与持有批次、持有期限和未来处置有关，派息时点的现金到账不一定等于最终税后收入。ETF基金分配也不能直接套用个股税务规则。

P0应将税务结果拆成：

- 已扣税额；
- 当前或有税负；
- 持续持有情景；
- 假设出售日情景；
- 规则版本及生效区间。

在交易批次或退出假设不足时，只输出税务情景或区间，不输出确定的“实际税后股息率”。

### 4. 数据时点必须从“公告日”升级为双时间契约

每条数据至少需要区分：

- 经济归属期或有效时间；
- 来源首次公开时间，精确到时区和时间；
- 系统首次观察或入库时间；
- 修订生效时间；
- 研究 as-of 时间。

需要保存业绩快报、正式财报、财报更正以及分红预案、批准、实施、变更或取消的版本链。同日收盘后发布的信息不能被视为当日收盘前已知。

### 5. 公司行动和收益不能依赖一个复权因子

P0样本至少建立可对账的三类记录：

- 原始价格或 NAV；
- 证券数量与公司行动；
- 投资者现金流。

股票市场价格总回报、ETF市场价总回报、ETF复权NAV总回报、标的指数价格/全收益回报和投资者实际现金流回报必须分开。禁止使用已经包含分红的复权价格后再次叠加现金分红。

### 6. ETF必须拆成指数层、基金层和投资者体验层

ETF名称不能代表真实策略，指数股息率也不能代表基金实际派息率。P0至少需要：

- 指数方法及版本；
- 指数成分与权重的适用日期；
- 基金合同收益分配条件；
- ETF实际派息；
- ETF市场价、NAV和基准总回报；
- 费率、跟踪差异和披露滞后。

组合穿透应同时显示 `holdings_as_of`、研究基准日和滞后天数。MVP不承诺任意历史日期的精确基金持仓。

### 7. “可持续分红”必须落到法律实体和现金约束

集团合并利润或普通口径自由现金流不等于母公司可分配现金。个股研究需要检查：

- 母公司未分配利润与法定分配约束；
- 子公司现金上划能力；
- 监管资本和债务契约；
- 维持性与扩张性资本开支；
- 周期正常化盈利和商品价格；
- 分红方案所处状态及适用股本。

缺少关键证据时，应进入“资料不足”或“观察”，而不是给出确定性目标价格。

### 8. 所有验收必须可量化

“正确、完整、一致、降低可信度、清楚展示”等表述不可直接自动验收。需要将测试改写为固定样本的 Given/When/Then，并定义：

- golden fixtures和期望值；
- 数值精度与对账容差；
- P0阻断字段；
- 缺失和冲突原因码；
- 结论降级规则；
- 输入数据manifest和输出hash；
- 代码、schema、解析器、公式、规则、交易日历和人工假设版本。

## 独立角色的关键补充

### 投资顾问的独有重点

- 风险不能只用波动或回撤，还要关注永久资本损失和购买力损失。
- 当前现金收入型与股息增长/总回报型应分轨研究。
- 高支付率不一定代表优秀，低分红但高回报再投资也可能创造更多股东价值。
- 需要明确持有后复核和退出触发器，而不只是更新数据。
- 最强的系统验收不是识别优质股，而是能够拒绝高股息陷阱，并识别“企业合格但组合不适合”。

### Coding专家的独有重点

- 当前“证券”概念承载过多语义，应拆分公司、证券份额、基金、指数、指数方法版本、持仓批次、来源文档、观测值、公司行动、分红事件、研究运行和假设集。
- 在确定数据供应商前，必须建立字段级数据可得性、许可、历史深度、成本、频率和替代来源矩阵。
- 需要采集可观测性、幂等重跑、schema drift、错误恢复、隐私、删除和导出规则。
- 首版产物应有明确输出契约，例如结构化数据、run manifest和可读研究卡，而不是先决定复杂UI。

### 量化与数据治理专家的独有重点

- 历史可投资全集必须保留退市、停牌、ST、基金清盘、转型、换码和基准变更，防止只研究当前存续标的造成幸存者偏差。
- 财务数据应保留“当时已知值”和“今天回看重述值”两套视图。
- 历史指数成分需要区分公告日、参考日和生效日。
- FCF、ROIC、历史分位、相关性、波动、回撤和分红削减共振均需定义公式版本、窗口和最小样本。
- MVP明确不做候选策略回测；若以后回测，应另立需求处理成交时点、停牌涨跌停、退市、交易成本、样本外验证和多重检验。

## 讨论中的分歧及收敛结果

### 分歧一：先做6个样本，还是11至16个样本

- 投资顾问初始建议8–12只股票与3–4只ETF，以覆盖投资反例和组合适配。
- Coding专家建议先做6个证券的数据可行性验证，再扩展。
- 量化专家建议先做6个证券Spike，正式MVP扩至8只股票与3只ETF。

**收敛结果**：采用两阶段样本。

- Spike：6个冻结样本——稳定普通工商企业1、资源或负自由现金流高息陷阱1、公用事业1、银行1、同指数或近似指数但派息机制不同ETF 2。
- 正式MVP：8只股票+3只ETF。新增样本用于覆盖特别分红或公司行动、第二只银行、消费或通信，以及发生指数方法差异或版本变化的ETF。

这些样本是测试夹具，不是推荐池。

### 分歧二：历史数据治理是否全部属于P0

- 投资顾问认为全市场历史可投资全集、完整指数历史和全量公司行动不应挤占投资P0。
- Coding与量化专家认为双时间、版本链和公司行动账本是可信结果的基础。

**收敛结果**：数据契约和schema属于P0；只在冻结样本上实现最小闭环。全市场历史回填、任意日精确ETF穿透和完整指数历史恢复延期。

### 分歧三：研究历史区间

- 技术与数据侧建议正式MVP以2019-01-01至2026-08-09为可控恢复区间。
- 投资侧指出该区间未必覆盖资源企业完整周期，不能据此证明跨周期分红持续性。

**收敛结果**：2019年至当前用于数据工程和可复现验收；投资结论在可得时使用更长历史或完整行业周期。若历史不足，必须降级结论，禁止把七年样本宣传为完整周期。

### 分歧四：投资政策与数据Spike的先后

**收敛结果**：两者可并行，但用途不同。数据Spike可以验证采集、公式和可复现性；在IPS与组合护栏确认前，不得输出“适合”或“组合合格”结论。

## 最终Top 5修订顺序

1. **重写MVP范围和投资决策边界**：加入最小IPS、组合硬护栏、合格/观察/排除/资料不足四态、Must/Should/Won’t以及明确延期项。
2. **修正投资指标语义与公式**：成本股息率退出决策排序；目标价改为收益率隐含价格；补税务情景、母公司可分红现金、周期正常化、独立估值和总回报否决。
3. **建立双时间领域模型**：稳定证券ID、历史状态、财报版本、分红状态机、公司行动/现金流账本、ETF指数与基金分层。
4. **验证数据源与可复现链路**：完成字段级来源/许可/成本矩阵、不可变原始文档与hash、run manifest、数据血缘、人工覆盖和版本管理。
5. **以冻结样本建立量化验收**：先用6个样本完成golden tests，再扩至8股+3ETF；定义容差、阻断字段、原因码、对账和端到端输出契约。

## Spike准入和退出门槛

### 准入

- PRD v0.2完成上述Top 5中的需求定义；
- 明确Spike的6个样本只用于测试，不构成推荐；
- 明确基准日、时区、价格时点和数据来源；
- 明确不做策略回测和正式候选输出。

### 退出

- 所有结论使用的数据均能追溯到原始来源、首次公开时间、版本和hash；
- 任一派生指标能够追溯到输入ID、公式版本、as-of和run_id；
- PIT测试无前视违规，重复事件为零；
- 分红、公司行动和总回报抽样对账通过；
- ETF指数、基金派息和总回报口径不混用；
- 关键字段缺失时能够进入“资料不足”，而不是生成伪精确数值；
- 系统能拒绝至少一个高股息陷阱样本；
- 系统能区分同指数或近似指数但派息机制不同的ETF；
- 系统能识别一个企业本身合格、但导致模拟组合集中度超限的案例；
- 相同输入快照和版本重复运行时，输出一致或所有差异均有解释。

## 复盘

### 做得好的地方

- 独立评审避免了工程可行性压过投资目的，也避免投资框架忽略数据偏差。
- 交叉回应后，三方没有停留在“补更多指标”，而是共同收敛到投资政策、数据契约、公式语义和验收门槛。
- 通过“高息陷阱、同指数不同派息、企业合格但组合不适合”三类反例，把抽象原则转成可测试行为。

### 暴露出的原PRD问题

- 把愿景、MVP和未来能力写在同一层级；
- 把“展示风险”写得比“如何判定适合”更具体；
- 对数据可得性、许可、时间语义和公式细节估计不足；
- 对税后收益、成本股息率和收益率隐含价格的表达仍可能误导投资决策；
- 验收标准偏描述性，尚未形成可自动验证的契约。

### 下一步建议

先将 PRD 修订为 v0.2，而不是立即编写采集代码。v0.2应新增四张核心规范表：

1. Must/Should/Won’t与阶段样本表；
2. 投资指标、收益和税费公式表；
3. 时间、版本与领域实体表；
4. 数据质量、阻断条件与golden test验收表。

评审最终状态：**有条件通过，允许进入PRD v0.2修订；通过P0与冻结样本验证前，不进入全功能实现。**
