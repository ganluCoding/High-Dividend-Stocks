## Problem Statement

用户希望在整体资产配置中，寻找适合作为高股息权益仓位的中国 A 股个股与境内上市 ETF。现有常见做法以“最近一次年度每股分红 ÷ 当前股价”计算静态股息率，再按5%、5.5%或6%等目标股息率反推价格。这种方法只能回答“历史分红不变时，对应的收益率锚点是多少”，不能回答未来分红能否持续、企业是否值得持有、ETF是否真的会派出相应现金，或者新增持仓是否适合用户的整个组合。

静态股息率容易混淆历史股息率、前瞻股息率、持仓成本股息率、税后现金回报、企业分红、ETF派息和含分红总回报。股息率上升也可能来自盈利恶化、周期见顶、监管资本不足或资产负债表承压造成的股价下跌。若缺少企业质量、现金约束、独立估值和组合适配判断，系统可能只是把“静态高息表”包装成一个更复杂的高息陷阱筛选器。

用户还没有提供完整的投资政策说明。高股息资产究竟用于消费现金流、分红再投资、降低权益波动还是追求股息增长，会改变“适合”的定义。如果没有现金需求、期限、权益上限、永久损失承受能力、集中度限制、账户与税务身份等信息，系统只能评价标的本身，不能宣称标的适合用户。

要形成可信的研究结论，还必须解决数据问题：公司公告与财务数据会被修订，分红方案存在预案、批准、实施、变更和取消状态，代码、股本、指数方法和基金基准会变化，ETF指数收益、基金NAV收益与实际派息不能重复计算。只保存当前快照或最终修订值会产生前视偏差、幸存者偏差和复权错误。

因此，用户需要的不是即时高股息排行榜或自动荐股工具，而是一套可复核、可更新、能拒绝资料不足和高息陷阱、并能放回个人组合语境中的研究系统。

## Solution

建立一个分阶段交付的高股息研究系统。系统先用冻结样本证明数据、公式、时间语义、税务情景和研究结论可以复现，再扩展到正式MVP。个股和ETF分开建模，共享证券主数据、研究基准日、来源文档、组合暴露和运行审计信息，但不共享无口径限定的“股息率”。

对个股，系统研究企业持续创造和分配现金的能力、母公司可分配现金、资本配置、资产负债表、行业周期、独立估值与组合适配；对ETF，系统分别研究指数规则、基金合同、实际派息、市场价格、NAV、跟踪质量、流动性和持仓披露滞后。系统输出事实、计算、假设与判断，使用风险否决和状态结论，不使用黑箱综合评分。

### 产品原则

1. 先定义“适合谁”，再判断“适合什么”。
2. 股息不是债券票息；现金收入与总回报必须同时展示。
3. 持仓成本股息率只用于回顾，不用于当前机会比较或排序。
4. “股息 ÷ 目标收益率”只得到目标收益率隐含价格，不得到内在价值。
5. 隐含价格必须接受企业质量、分红安全、独立估值和组合护栏否决。
6. 个股、指数、ETF基金与投资者现金流分层建模。
7. 关键数据不足时不出结论，不使用伪精确估计填补。
8. 所有输入、公式、版本、人工假设和输出均可追溯和重算。

### 决策状态

标的研究状态与组合适配状态分开，确保可以表达“企业合格，但组合不适合”。

标的研究状态：

- **资料不足**：P0阻断字段缺失、冲突未解决或数据许可不允许使用。
- **排除**：触发明确否决条件，例如可持续分红证据失败、重大财务/治理约束或独立估值不支持。
- **观察**：证据基本可用，但存在估值、周期、分红状态、质量或流动性不确定性。
- **合格**：证据充足，未触发否决，且风险反证和失效条件明确；不等于建议买入。

组合适配状态：

- **未评估**：IPS或持仓数据不足；
- **适配**：加入模拟仓位后未触发组合硬护栏，且满足该IPS明示的仓位任务及对应最低目标；只有消费现金流任务才把现金覆盖作为必要条件；
- **超限**：触发任一发行人、行业、经济驱动、流动性或权益风险上限。

状态优先级为：资料不足优先于数值输出；排除优先于隐含收益率；组合超限不得被标的合格覆盖。

### 核心输出

- 个股研究卡：商业与行业特征、分红生命周期、母公司可分配现金、分红覆盖、财务安全、治理、独立估值、隐含价格、风险反证和状态。
- ETF研究卡：指数方法版本、成分与权重日期、基金合同派息规则、实际派息、费用、市场价/NAV/基准总回报、跟踪、流动性和披露滞后。
- 可比矩阵：在相同as-of和明确指标口径下比较候选，但不把个股与ETF的派息率混成一个通用字段。
- 组合报告：直接持股与ETF穿透后的发行人、行业、经济驱动、集中度、现金流月份及适配状态。
- 审计报告：来源、公开时间、观察时间、版本、hash、公式、假设、缺失、冲突、运行清单和输出hash。
- 运行差异：新增、修订、失效、被替代数据及研究状态变化原因。

### 成功标准

- 100%用于结论的关键数据可追溯到来源文档、首次公开时间、版本和内容hash。
- 100%派生指标可追溯到输入ID、公式版本、研究as-of和run_id。
- PIT golden tests的前视违规为0，重复分红事件为0。
- 相同输入快照、代码、公式、规则和假设重复运行时，规范化输出hash一致。
- 关键字段缺失时输出“资料不足”，不产生可持续股息、隐含价格或确定税后值。
- 系统能排除至少一个静态股息率很高但分红不可持续的陷阱样本。
- 系统能区分同一或近似指数但派息政策不同的两只ETF。
- 系统能识别至少一个“标的合格、组合超限”的测试案例。
- 所有现金分红、公司行动、ETF派息和总回报对账均在声明容差内。
- 任一报告都明确区分事实、计算、假设和判断。

## User Stories

1. [MUST] 作为投资者，我希望说明高股息仓的任务，以便区分消费现金流、分红再投资、股息增长和权益防御。
2. [MUST] 作为投资者，我希望将人民币200,000元记录为本研究本金，并与总净资产、负债和应急金信息分开，以便本金设定不被误解为默认满仓。
3. [MUST] 作为投资者，我希望设置投资期限、权益上限和流动性需求，以便约束候选载体。
4. [MUST] 作为投资者，我希望设置最大回撤和最大永久资本损失边界，以便区分价格波动与投资逻辑损失。
5. [MUST] 作为投资者，我希望设置发行人、行业、经济驱动、央国企和低流动性上限，以便形成组合硬护栏。
6. [MUST] 作为投资者，我希望记录账户和税务身份，以便选择适用的税务情景。
7. [MUST] 作为投资者，我希望在IPS不完整时看到“未评估”，而不是收到伪个性化的适合结论。
8. [SHOULD] 作为投资者，我希望设置年度现金金额和需求月份，以便评价现金流覆盖与缺口。

16. [MUST] 作为研究者，我希望记录公告、登记、除息和支付时间以及适用股本，以便正确计算收益与现金到账。

## Implementation Decisions

### 投资指标、收益与税费公式

所有公式均绑定公式ID、版本、as-of、输入ID、币种、单位、交易日历和舍入规则。内部计算使用未格式化精度，展示层单独舍入。

| 指标 | 规范定义 | 决策限制 |
|---|---|---|
| 上一完整财年股息率 | 上一完整财年已实施现金DPS ÷ as-of未复权收盘价；常规与特别分红分列 | 仅历史描述 |
| TTM股息率 | as-of前12个月内以除息日计的已实施现金DPS合计 ÷ as-of未复权收盘价 | 不能视为未来承诺 |
| 已公告股息率 | 已批准或已进入实施阶段但尚未支付的DPS ÷ as-of未复权收盘价；按状态分列 | 预案不得混入已批准值 |
| 保守前瞻股息率 | 对应情景的可持续DPS ÷ as-of当前可变现价格 | 需要可持续分红证据与独立估值 |
| 持仓成本股息率 | 指定历史期间实际收到的现金分红 ÷ 对应持仓批次成本 | 只回顾，不排序、不用于继续持有判断 |
| 税务情景股息率 | 情景DPS扣除已知或假设税负后的金额 ÷ as-of当前价格 | 必须声明持有/退出假设和税规版本 |
| 目标收益率隐含价格 | 情景可持续DPS ÷ 用户目标收益率 | 不是内在价值；独立估值可否决 |
| 利润支付率 | 对应期间归属普通股股东的现金分红 ÷ 可比口径归母净利润 | 负利润、特别分红和跨期需单列 |
| 可分配现金覆盖 | 对应期间可分配现金 ÷ 现金分红 | 普通工商、银行等使用行业版本公式 |
| 股票总回报 | 基于原始价格、公司行动和现金分红账本计算的持有期TWR | 禁止复权价后重复加分红 |
| ETF市场价总回报 | ETF市场成交价与基金实际分配构成的TWR | 反映投资者二级市场体验 |
| ETF复权NAV总回报 | NAV及基金分配构成的TWR | 用于跟踪差异，不重复叠加派息 |
| 基准总回报 | 对应版本指数的全收益或净收益口径 | 必须记录指数类型和方法版本 |
| 跟踪差异 | ETF复权NAV总回报减基准总回报 | 市场价折溢价影响另列 |

可持续DPS不采用跨行业统一黑箱公式。普通工商企业的透明基准由正常化盈利、审慎支付率、可分配现金、维持性资本开支、债务与法律分配约束共同限制；银行使用盈利、资本充足、资产质量、监管与管理层分配政策模型。任一约束缺失或失败时，系统不得给出“合格”状态。

独立估值至少采用一个行业适配的非股息率方法，并记录假设与版本。若独立估值、正常化盈利或总回报判断与目标收益率隐含价格冲突，研究状态只能是观察或排除，不得因股息率达标升级。

税务模型区分投资者类型、证券类型、持仓批次、规则生效区间、已扣税、或有税负和假设处置日。ETF基金分配、个股分红和基金资产内部税负分别建规则。信息不足时只输出税前结果和税务情景，不输出确定税后现金。

|---|---|---|

真实股票样本的Spike级可持续DPS合同如下：

- 普通工商与公用事业：使用正常化归母EPS、审慎支付率、母公司可分配现金/股、维持性资本开支后现金覆盖、净债务与分配约束；任一硬约束缺失即资料不足；
- 资源周期：在普通工商合同基础上，正常化盈利至少覆盖默认区间并对周期峰值进行压力调整；只有当来源充分时才给出观察或排除；
- 银行：使用归母EPS、支付率、核心一级资本充足率、资本充足率、资产质量、监管与公司分红政策；不使用普通工商FCF；
- 独立估值：普通工商/公用事业/资源至少选择正常化PE、PB-ROE或企业价值现金流中的一个行业适配方法；银行使用PB-ROE与历史/同业交叉检查。Spike若尚未冻结阈值，真实样本状态只能是资料不足或研究资料，不得伪造合格结论。

首个Spike冻结两套截至research_as_of核验的规则版本：

### 总回报递推规则

- 总回报区间为前一交易日收盘至当前交易日收盘；价格使用未复权收盘价。
- 股票和ETF市场价总回报在除息日确认分配权益，并假设税前现金在除息日收盘价再投资；投资者现金流账本仍在实际支付日记录现金到账，两者不得混用。
- 对无公司行动的普通期间，单期总回报为`(P_t + D_t) / P_{t-1} - 1`，其中`D_t`仅包括该交易日除息的每份现金分配。
- 再投资份额为`D_t / P_t`；后续收益基于增加后的份额计算。ETF复权NAV总回报使用相同逻辑但以单位NAV和基金单位分配替代市场价。
- 非交易日不生成市场收益观测；现金支付可以在自然日现金流账本出现。区间端点使用交易所交易日历。
- 送股、转增或拆并股先在除权日开盘前调整持有数量，再用原始收盘价计算市值；`SYN-CA-001`固定为1股、前收盘10元、每1股转增0.5股、除权收盘6.6666666667元、无现金，唯一预期总回报为0。
- 配股、换股、退市和基金清盘在首个Spike不进入真实样本收益验收；若数据中出现，必须使用单独明确的认购/放弃/终值假设，否则相关总回报为资料不足。
- 基准收益优先使用指数公司发布的相应全收益序列；若只有价格指数，禁止用价格指数替代全收益指数计算跟踪差异。
- 1bp容差指收益率绝对误差0.0001；直接算术公式仍使用相对误差不超过1e-8。

分红事件的稳定逻辑键为`instrument_id + profit_period_end + distribution_type + installment_no`。`installment_no`在同一利润归属期内按公司披露的方案批次确定，不用支付年份推断。`dividend_event_id`为该逻辑键的SHA-256摘要；`version_id`为`dividend_event_id + published_at + source_document_hash`的SHA-256摘要；每个新版本记录`supersedes_version_id`。同一来源文档hash只能生成一次版本记录。

若不同来源无法确定是否属于同一逻辑事件，记录为`DIV_EVENT_IDENTITY_CONFLICT`并进入人工复核，不自动合并。利润归属期间、公告时间、登记日、除息日和支付日分别存储。TTM只汇总as-of前12个月内以除息日计、当时状态为实施安排或已支付且未取消的唯一逻辑事件；已批准未实施方案单列，不进入TTM。

### 时间与版本契约

- 所有时间使用带时区的时间戳，默认展示时区为Asia/Shanghai。
- `valid_time`表示经济事实适用的时间或期间；`published_at`表示来源首次公开时间；`observed_at`表示系统首次取得时间；`superseded_at`表示被后续版本替代时间；`research_as_of`表示本次研究截止时点。
- “市场当时可知视图”选择`published_at <= research_as_of`的事件版本，并在每个逻辑事件内取published_at最大的版本；若同一时刻有多个冲突版本则阻断。
- “本系统当时持有视图”在市场可知视图基础上增加`observed_at <= research_as_of`约束，用于重现本系统实际运行；正式研究默认使用市场当时可知视图，运行审计同时记录系统持有视图差异。
- `superseded_at_market`等于后继版本的published_at，`superseded_at_system`等于后继版本的observed_at；版本区间左闭右开。
- 若来源只有日期没有时刻，记录时间精度与不确定性；EOD研究不得将其视为同日收盘前已知，除非有可验证发布时间。
- 保留“当时已知视图”和“最新重述视图”，两者不得混合生成历史研究结论。
- 分红事件状态机为：预案 → 董事会通过 → 股东大会批准 → 实施安排 → 已支付；任一阶段可进入变更或取消。每次变化生成新版本，不覆盖旧版本；取消是终止状态，变更必须指向被替代版本。
- 指数调仓保存公告日、参考日和生效日；基金持仓保存披露基准日和公开时间。
- 人工判断采用追加式覆盖，不直接修改来源事实，并包含作者、理由、原值、有效期和复核状态。

### 公司行动与收益账本

- 原始价格/NAV账本保存未复权数据及交易状态。
- 数量与公司行动账本处理拆并股、送转、配股、增发、换股、份额折算和终止状态。
- 现金流账本处理个股分红、ETF分配、税、费用和其他明确现金事件。
- 每股历史可比调整、证券持有数量变化和投资者实际现金流分别计算，禁止用一个复权因子替代三者。
- 配股、换股、退市和基金清盘必须有明确终值或资料不足状态；未覆盖的事件不得静默当作零收益。
- 供应商复权因子和内部重算结果分别保留，并通过冻结样本对账。

| 数据域 | 首选来源类别 | 必须验证的事项 |
|---|---|---|
| 公司公告、财报和分红 | 公司与交易所一级披露 | 历史深度、发布时间、修订链、文档可存档性 |
| 价格、交易状态、公司行动 | 交易所或获许可行情源 | 原始/复权口径、停牌、退市、授权与频率 |
| ETF合同、公告、NAV和持仓 | 基金管理人、交易所与法定披露 | 派息规则、NAV口径、持仓滞后、基金状态 |
| 指数方法、成分和历史值 | 指数公司 | 方法版本、成分许可、全收益口径和再分发限制 |
| 税费与监管规则 | 财税和监管机关 | 生效区间、适用对象、更新机制 |
| 行业与参考数据 | 官方、指数公司或获许可供应商 | PIT分类、历史状态、可替代性和成本 |

每个MUST字段记录primary/fallback、字段覆盖率、历史深度、更新频率、成本、稳定性和PIT能力，并分别记录公开访问、自动采集、本地保存、内部计算、衍生结果展示、原始数据导出或再分发六类权利状态。状态只能是`allowed`、`restricted`、`unknown`或`not_applicable`。许可未确认的数据仅可用于人工网页核验或一次性、操作员触发且不对外输出原始数据的本地可行性调查；不得据此启用定时、批量、生产化采集，不得导出或再分发。关键来源不可用时进入资料不足。

首轮数据采集采用以下权限边界：公司、交易所、指数公司、基金管理人及财税机关页面作为一级事实来源，保存URL、公告编号、公开时间和内容hash；是否保存完整文档由站点条款矩阵决定。AKShare、BaoStock及其上游公开接口只作为便利采集层，原始结果仅用于一次性本地内部研究，在来源条款核验前不启用定时采集或对外再分发。研究报告只展示必要派生字段和一级来源链接。

每次ResearchRun至少固化：run_id、research_as_of、原始文档与响应hash、source URL或公告编号、parser版本、schema版本、公式/规则版本、单位与币种转换版本、交易日历版本、证券主数据版本、公司行动版本、指数方法与成分快照版本、税规版本、代码版本、依赖锁、AssumptionSet、用户参数、输入manifest和输出hash。

### 输出Schema、原因码与确定性Hash

Spike的结构化输出至少包含`schema_version`、`instrument_id`、`research_as_of`、`evidence_status`、`instrument_status`、`portfolio_status`、`facts`、`metrics`、`assumptions`、`reason_codes`、`source_document_ids`、`formula_versions`和`input_manifest_hash`。所有字段均定义类型、是否必填和单位；未知值使用`null`，不得使用0或空字符串代替。

首版机器原因码冻结为：

- `MISSING_CRITICAL_FIELD`、`SOURCE_CONFLICT`、`PIT_VIOLATION`、`DIV_EVENT_IDENTITY_CONFLICT`；
- `DIV_CASH_COVERAGE_FAIL`、`DIV_DEBT_CONSTRAINT_FAIL`、`DIV_CAPITAL_CONSTRAINT_FAIL`、`CYCLICAL_NORMALIZATION_FAIL`；
- `VALUATION_CONFLICT`、`TAX_CONTEXT_INCOMPLETE`、`ETF_BENCHMARK_UNKNOWN`、`HOLDINGS_STALE`；
- `PORTFOLIO_ISSUER_LIMIT`、`PORTFOLIO_INDUSTRY_LIMIT`、`LICENSE_RESTRICTED`、`UNSUPPORTED_CORPORATE_ACTION`。

用户文案与机器原因码分开版本化。确定性hash采用SHA-256，输入为UTF-8规范化JSON：对象键按Unicode码点排序，数组按领域主键排序，时间统一RFC 3339带时区，数值以规范化十进制定点字符串表示，缺失为`null`，不含空白。随机run_id、生成时间、绝对文件路径、日志和抓取耗时不进入输出hash；它们保留在run元数据中。相同规范化输入、公式、规则和假设必须得到相同hash。

### 数据质量与阻断规则

| 规则 | 默认门槛 | 失败行为 |
|---|---|---|
| 关键字段完整率 | 100% | 对应结论为资料不足 |
| 来源文档、公开时间、版本、hash覆盖 | 100%用于结论的数据 | 阻断派生结论 |
| PIT前视违规 | 0 | 整个run失败 |
| 重复分红事件 | 0 | 分红相关结论失败 |
| 直接算术公式误差 | 相对误差不超过1e-8，展示舍入除外 | 测试失败 |
| 现金分红金额对账 | 适用股数×每股金额与披露总额在来源精度容差内 | 标记冲突并阻断可持续分红 |
| 股票/ETF总回报对账 | 默认1bp；数据精度要求其他容差时必须在fixture声明 | 收益与跟踪结论失败 |
| 指数或穿透权重 | 已知部分、现金与未知部分之和在声明容差内为100% | 穿透状态资料不足 |
| ETF基准及方法版本 | 100%已知 | 阻断ETF策略和跟踪结论 |
| 可持续分红关键约束 | 100%满足对应行业模型 | 不输出隐含价格或合格状态 |
| 税务身份/批次/规则 | 完整才允许确定值 | 只输出税前和情景区间 |
| 重复运行一致性 | 同一manifest的规范化输出hash 100%一致 | 可复现性验收失败 |
| 人工覆盖审计字段 | 100%含作者、时间、理由、原值和有效期 | 覆盖无效 |

数据质量维度包括validity、completeness、timeliness、consistency和uniqueness。缺失值不得默认为零。任何降级或阻断必须使用机器可读原因码和用户可读说明。

### 行业模型范围

- Spike只实现普通工商企业、公用事业、资源和银行所需的最小透明模型；允许共用基础字段，但不得把普通工商企业FCF公式用于银行。
- 正式MVP仍不纳入保险专属模型。
- 行业专属估值与分红约束分别定义，例如银行使用资本与资产质量约束，资源企业使用周期正常化价格和资本开支。
- 无适用行业模型时输出资料不足，不使用通用阈值强行排名。

### 组合规则

- 组合护栏来自IPS，可配置但不可由候选自身表现自动放宽。
- Spike的最小组合算法是MUST：使用`SYN-IPS-001`和固定测试权重，只计算单一发行人及行业上限，并验证超限原因码。用户真实IPS不完整时，真实组合状态保持未评估。
- 穿透同时保留直接持股、指数理论权重和基金最近披露持仓，不把后两者视为同一精度。
- 报告显示`holdings_as_of`、`research_as_of`、`lag_days`、现金和未知权重。
- 正式MVP再增加ETF完整穿透、经济驱动和现金流月份等简单可解释暴露；复杂风格因子和分红削减共振延期。
- 企业研究合格但模拟加入后任一硬护栏超限时，组合状态为超限。

### 输出与非功能要求

- Spike和MVP的最小产物为：结构化规范数据、ResearchRun manifest、Markdown或HTML研究卡、可比矩阵、组合报告和审计报告。
- 输出中的每个数值带口径、单位、币种、截止时点和状态；事实、计算、假设和判断使用不同标签。
- 单用户首版本地运行，持仓与税务身份默认只保存在本地；日志不得包含不必要的持仓明细。
- 支持导出和删除用户输入；删除用户输入不删除合法保存的公开来源数据。
- 采集任务需要幂等重跑、最后成功时间、数据新鲜度、记录数、缺失率、冲突率、解析失败和schema drift状态。
- 数据或规则更新不覆盖旧run；新run输出added、changed、superseded、invalidated及原因码。
- Spike不设全市场性能目标；正式MVP的运行时间和容量目标在数据可行性通过后确定。

## Testing Decisions

### 测试原则与最高层验收缝隙

优先测试用户可见行为，不绑定内部存储和函数。最高层验收路径为：

> 导入6个冻结样本及最小模拟IPS/持仓 → 执行as-of研究 → 生成4张个股卡与2张ETF卡 → 生成对比与组合适配 → 输出审计manifest → 使用同一输入重复运行并比较hash。

测试数据使用已核验的一级来源冻结副本和明确期望值。每个测试采用Given/When/Then，包含输入manifest、预期状态、预期数值、容差和原因码。

所有fixture必须是机器可读并包含`fixture_id`、适用instrument_id、research_as_of、input_document_hashes、适用测试编号、输入值、唯一预期状态、精确预期数值、容差和原因码。真实6样本用于数据可得性与研究流程；`SYN-TRAP-001`、`SYN-CA-001`和`SYN-IPS-001`用于确定性边界行为。fixture清单变更必须提升版本。

### Golden tests

1. **每十股分红换算**：给定每十股现金分红和未复权收盘价，计算每股金额、历史股息率及隐含价格，内部相对误差不超过1e-8。
2. **同日收盘后公告**：给定收盘后发布的分红方案，当research_as_of为当日收盘时，该方案不得进入已知信息；下一可用时点方可出现。
3. **财报与方案修订**：给定原始公告和修订公告，当时视图使用原版本，最新视图使用修订版本，旧版本仍可追溯。
4. **分红状态机**：预案、批准、实施、变更和取消不得被计算为同一已支付事件，重复事件数必须为0。
5. **特别分红**：给定一次性大额分红，系统将其与常规基线分开，默认不进入可持续DPS。
6. **公司行动**：使用`SYN-CA-001`，1股在每1股转增0.5股后成为1.5股，前收盘10元、除权收盘6.6666666667元、无现金，唯一预期总回报为0；真实配股不在首轮算法验收范围。
7. **高息陷阱**：使用`SYN-TRAP-001`，唯一预期状态为“排除”，原因码同时包含`DIV_CASH_COVERAGE_FAIL`和`DIV_DEBT_CONSTRAINT_FAIL`；不得以资料不足通过，也不得输出可操作隐含价格。
8. **银行例外**：给定银行样本，系统使用资本、资产质量与银行盈利口径，不调用普通工商企业FCF否决。
9. **ETF派息差异**：给定同一或近似指数但合同派息规则不同的两只ETF，指数收益、NAV总回报和实际派息分别输出，不推导相同派息率。
10. **ETF总回报对账**：NAV变动与基金分配计算的总回报和复权NAV回报在默认1bp或fixture声明容差内一致，派息不重复加入。
11. **税务情景**：使用1,000股、每股分红0.50元fixture，持有20日、180日、400日后处置的预期或有税款分别为100元、50元和0元；ETF 1,000份、每份分配0.10元在冻结规则下预期税额0元。批次或税规缺失时不得输出确定税后值。
12. **组合超限**：使用200,000元本金和`SYN-IPS-001`。模拟组合原有同一发行人敞口16,000元，新增10,000元后为26,000元，占本金13%，超过10%上限；标的状态保持合格，组合状态唯一为超限，原因码为`PORTFOLIO_ISSUER_LIMIT`。
13. **资料不足**：删除任一阻断字段后，对应指标和状态被阻断并返回确定原因码，不以零或默认估计代替。
14. **许可门禁**：给定再分发权限未确认的数据源，内部可行性状态与可导出状态必须分离，禁止导出受限原始数据。
15. **可复现运行**：相同输入manifest、代码、公式、规则和假设运行两次，规范化输出hash必须完全一致。
16. **运行差异**：新增或修订一条分红公告后，新run必须列出changed或superseded记录、受影响指标和状态变化原因，旧run保持可读取。

### Spike退出门槛

- 上述适用golden tests全部通过；
- 关键字段完整率100%，PIT违规0，重复分红事件0；
- 所有用于结论的数据具备来源、公开时间、版本和hash；
- 所有派生指标具备输入ID、公式版本、as-of和run_id；
- 分红、公司行动、股票总回报、ETF总回报在声明容差内完成对账；
- 高息陷阱、ETF派息差异和组合超限三个反例均产生预期状态；
- 数据来源可行性矩阵覆盖所有MUST字段，许可或成本缺口有明确处置；
- 同一manifest重复运行输出一致；
- 未解释的关键冲突为0；
- 审阅者确认系统没有输出推荐语言或确定性收益承诺。

## Out of Scope

- 在Spike通过前进行全市场自动采集、排名和正式候选输出。
- 自动买卖、券商下单、条件单、自动调仓和收益保证。
- 短线择时、K线、技术指标、涨跌预测和市场情绪交易。
- 完整全资产最优配置；本产品只执行高股息权益仓的最低组合护栏和适配检查。
- 港股、美股、REITs、债券、期权、期货及非境内上市基金。
- 高频或逐笔行情，以及依赖盘中采样的精确实时买卖价差。
- 任意历史日期的精确ETF实际持仓穿透；MVP使用指数理论暴露和最近披露基金持仓并标记滞后。
- 全市场历史可投资全集恢复、完整历史指数方法重建和历史一致预期vintage回放。
- 候选策略回测、因子收益归因、分红削减共振模型、多重参数搜索和样本外检验。
- 保险及其他尚未定义专属数据与公式的行业模型。
- 依赖不可解释的黑箱模型预测股息或价格。
- 将股票回购、资本返还或清算分配直接等同于常规现金分红。
- 将特别分红或最近一次ETF派息默认年化。
- 使用持仓成本股息率进行候选排序或继续持有判断。
- 将目标收益率隐含价格描述为内在价值、目标价或买入建议。
- 在税务信息不足时输出确定税后收益，或提供个别化税务和法律意见。
- 在数据质量不足时强行输出可持续分红、隐含价格、合格状态或组合适配。
- 实时UI、多人协作、云端账户和复杂权限系统。

## Further Notes

- 本PRD延续“买企业而非只买股票”的原则：分红是企业经济质量、现金创造、法律实体约束和资本配置共同作用的结果。
- 初始参考图片仅用于确认“由历史分红反推收益率锚点”的需求模式，不作为当前行情、分红或样本名称的数据来源。
- 风险同时包括波动、回撤、永久资本损失、购买力损失、分红削减和组合集中；名义现金流稳定不等于真实购买力稳定。
- 高支付率可能代表资本纪律，也可能意味着企业缺乏再投资机会或正在透支资产负债表；低分红但高回报再投资也可能创造更多股东价值。
- 当前目录没有项目Issue跟踪器，因此本PRD继续以本地文档作为产品基线。初始化项目管理后再发布Issue并应用`ready-for-agent`标签。
- v0.3在两轮三角色评审基础上，进一步冻结人民币200,000元研究本金、6个真实数据样本、research_as_of、确定性反例、事件身份、双时间查询、总回报递推、税务数值fixture、原因码和确定性hash规范。
- 本版仍不决定具体开发语言、存储引擎、供应商和UI。Spike的数据可行性矩阵与测试结果将为后续技术设计提供约束。
- 当前状态允许执行受限的本地数据可行性Spike与确定性测试，不代表批准正式MVP、生产化数据采集或形成投资建议。
